## 原版入口与修改范围

Mixin配置：`differentenchant.mixins.json`，required=true且每个注入要求命中，接口不符会直接启动失败。

| 入口 | 修改范围 / 所有权 |
| --- | --- |
| `EnchantmentHelper.doPostAttackEffectsWithItemSource` TAIL | 仅成功近战且带借火、攻击者实际燃烧时处理状态。没有额外hurt调用，没有定时器/冷却 |
| `EnchantmentHelper.processAmmoUse` RETURN | 仅CrossbowItem及继承路径、仅Items.ARROW、仅有回羽且原消耗正数时判定；不改发射阶段 |
| `BowItem.releaseUsing` 对 `getPowerForTime` 的调用 | 使用本次弓物品的疾弦等级计算同一封顶power；0级与原公式一致，不改弩或全局静态蓄力函数 |
| 客户端 `UseDuration.useDuration` RETURN | 对带疾弦的BowItem缩放原版物品模型的蓄力时间属性 |
| `ServerLevel.gameEvent` HEAD | 仅过滤静步印玩家正常行走的STEP，不改音效调用、不改客户端声音或其他GameEvent |
| `Player.travel` TAIL | 服务器/客户端共用纸鸢水平公式；配置在JOIN时由服务器发送；不改Y、重力、掉落伤害或位置 |
| `ThrownTrident.onHitEntity` / `hitBlockEnchantmentEffects` HEAD | 从三叉戟自身保存的武器读取逆潮，命中一次启动独立短场，不依赖之后手持物 |
| `AbstractArrow.onHitEntity` HEAD | 格挡满足原版盾生效、时间、正面、无穿透及安全出口时取消原命中并复用该箭；其他情况完全走原版 |
| `ServerTickEvents.END_SERVER_TICK` | 逆潮区域更新、每秒倒影目标、星桥边缘采样；无全世界实体扫描 |
| 原版 `Display.BlockDisplay` / `DisplayRenderer` | 倒影是仅本客户端的不可碰撞轮廓，星桥是服务器注册的noSave实体并提供真实OWNER碰撞；两者都不写方块 |

配置：`config/differentenchant-lost.properties` 的 `air_drag`、`air_control`各三个数，前者限制0.7–1，后者0–0.05，拒绝NaN/越界；服务器加入同步，不允许客户端决定研究答案或世界效果。修改后重启服务器。

## 明确的玩法边界

- 静步印不屏蔽疾跑、HIT_GROUND落地、挖掘、开箱等事件，不加潜行速度、不静音。直接踩上尖啸体的物理触发、监守者嗅探/碰撞等仍有效；它不是监守者免疫。
- 借火遇`fireImmune()`目标时不转移也不熄灭自己；有火抗药水的普通生物仍可接收燃烧状态，伤害照原版火抗规则。保留目标已有的更长燃烧，不叠加伤害；自身超出上限的余火随熄灭消失。
- 回羽要求原生`getProjectile`能找到至少一支弹药。药箭、光灵箭和烟花不受影响；多重射击的副弹仍走原版forceInfinite，不重复掷骰。节省主弹得到的CHARGED_PROJECTILES携带原版INTANGIBLE_PROJECTILE，射出后不可在生存拾回，不进行退款。
- 疾弦不自动发射，满蓄力后继续按住仍能瞄准。最大速度、伤害公式、暴击增幅和弹药/耐久支付沿用原版；不是把72000使用时间随意改短。
- 纸鸢排除地面、水/熔岩、游泳、鞘翅、创造飞行、旁观、乘骑、攀爬、激流；只允许平滑水平阻尼/微调。轨迹中两组Y/纵速逐采样完全一致；首帧水平速度存在初始化差异，因此不把总位移差当严格平衡结论。III水平速度在连续采样中明显衰减，右方向输入确实改变Z落点。参数仍待试玩。
- 格挡尊重原版盾抬起延迟与伤害拦截组件；穿透箭保持原版绕盾语义。出口从身体前方的安全位置开始，朝向取视线、Y至少朝上约0.16，再归一化；空间不足不强行穿墙，退回原版格挡。原箭实体ID、普通/药箭/光灵类型、武器/药水数据与拾取标记不替换，归属交给格挡者，保留原版重力。不是自动追踪，也不生成第二支箭。
- 逆潮不改水源、不改地形、不对物品/全部实体加速；只查局部AABB内最多32个符合条件的活体，排除场主人、旁观者和飞行玩家。每人最多2场、全服最多32场，重叠加速度封顶0.06，水平速度封顶0.4，Y不加速，遮挡和未加载射线路径不牵引。忠诚照常回收；激流没有投掷命中实体，不产生漩涡。
- 倒影目标由`differentenchant:reflection_targets`方块标签决定，默认无矿石、无容器库存数据。每次最多8个坐标，扫描不获取区块。客户端用最多8个原生玻璃BlockDisplay的淡蓝发光轮廓，仅本客户端可见，30刻无更新自动清除；离水/摘帽更快清除。不更改头盔夜视或其他视觉属性。
- 星桥要求上一采样在真正方块支撑、当前刚离开且水平位移合理、疾跑且没有向上跳跃。后续按水平位移单位向量延伸，支持斜向；天然地面重新踏实且冷却到期前不能重复触发。每块检查完整碰撞区域的已加载区块与原生方块碰撞，中心须为空气且无流体；遇实体地形停止，不覆盖容器或方块。落脚点只对主人碰撞，其他玩家不会继承；不可采掘、无战利品、不可召唤，最多存活两秒，离远/摘靴/死亡/登出清除，卸载不保存。冷却写世界SavedData，不靠登出或换装备重置。

## 旧世界目录兼容

旧目录永不扩展会使旧世界正常研究永远得不到新九项；无条件重算则会覆盖旧成果。0.9.0采用一次性的`catalogueRevision=1`：

1. 原`outcomes`全部保留，包含任一玩家已发现的客观答案；UUID发现集合原样保留。
2. 原种子、输入weight/maxLevel和规则/池权重完全保留。
3. 只追加`differentenchant:batch_two`标签中的已注册输出，旧目录条目不覆盖。
4. 只有从未固定、从未向玩家展示真实结果的未知组合使用扩充目录。既有真实预览都来自固定成果，不变。
5. 同一修订不会再次追加或随reload继续洗牌。未来更多输出仍需新的明确迁移。

实测96个旧固定配方在扩池、重复迁移、JSON和原生NBT重载后完全一致；8,256个原版书组合中6,151个未固定结果变化，所有组合的层级选择及卷轴分支逐项不变。新目录17种均能研究；相邻世界种子有7,801个结果不同。详细新旧次数与原始报告见[验证目录](validation/lost-batch-two/README.md)。

## 完成状态与后续试玩

九项均为“已实现且已实机验证的初版”，没有仅Tooltip的项目，也没有把粒子当星桥碰撞。没有Lv.3、额外工具差异效果、遗迹、维度或祛魔机改动。

需要后续审核的是玩法强度/手感、格挡窗口和视觉节制。尚未进行两台独立客户端高延迟对战、完整整合包/渲染模组组合和长期极限数量压力；当前多人覆盖是正常ServerPlayer的服务端测试，客户端是实际本地集成服。星桥不写地形且不保存实体，服务端重启会消失；这不等于对操作系统断电提供跨文件原子保存保证。
