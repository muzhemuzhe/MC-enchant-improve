# 设计笔记（非最终机制规格）

## 已确定

1. 模组不是独立附魔祭坛：它重做的是原版附魔台。
2. 必须由 3×3×2（18 个格位）搭出、并形成视觉上统一的大型机器。
3. 附魔台等级、有效书架数量共同影响随机附魔分布。
4. 高等级并非高级附魔的硬性解锁条件：在所有其他正常限制满足时，最低机器等级也应允许高级附魔和较高级附魔等级以**严格大于零**的概率出现。
5. 高等级机器应在可比较的条件下提高获得高价值结果的概率。这里的“高级”需要进一步拆成「附魔种类稀有度」和「单种附魔的等级」，避免含糊。
6. 两种模式：随机、指定。第四轮指定模式使用铭纹石逐级升级，30级为门槛，每步暂耗5–8经验等级，高机器等级可降低费用；这是可配置的临时数值。
7. 后续可能加入宝藏附魔、原创附魔；应从 registry/tag 动态发现其他模组附魔。
8. 书架仍是机器之外的环境结构，不要把它误写成仪式基座。
9. 原版附魔台保留配方、放置、采集掉落和方块实体，但不再作为独立附魔设备；只能通过当前多方块机器使用随机/指定模式。普通右击与组装失败均不打开原版GUI，拆解恢复的附魔台同样适用。
10. 原版附魔台未来还将作为独立新村民职业“附魔师”的工作方块；当前不注册职业、POI或交易，不改原有村民交易。

## 暂缓决策

- 设备等级一共有多少级、由材料还是内部升级驱动；临时构造模板只是用来跑通流程。
- 书架影响“附魔强度分布”、选项数量还是费用（可以多维，不要先假定“更多书架只提升上限”）。
- “指定费用 > 随机附魔经验期望”：是高于一次随机附魔的期望费用，还是高于刷到同一目标的期望总费用？两者差别极大，**不能在未确认前写死数值**。
- 宝藏附魔的获得条件、权重，以及模组附魔对其标签/物品匹配的支持。
- 模型美术、动态发光、动画、音效和 UI。

## 第一轮临时 3×3×2 配方（完全可修改）

上层 y=1（俯视）：

    A O A
    O E O
    A O A

下层 y=0（俯视）：

    D D D
    D D D
    D D D

E = 原版附魔台（激活位置，中心）；A = 紫水晶块；O = 黑曜石；D = 磨制深板岩。

这 18 个格位仅是测试**形成/拆解/保存与渲染**的方便样例，并非定稿配方、升级材料或附魔逻辑。

## 架构倾向

- `StructurePattern`: 仅定义局部坐标和匹配规则，便于以后换正式配方；检查水平 4 个方向。
- `StructureValidator`: 在服务端验证 18 个格位、检查已加载区块，返回可靠的 formation plan；检查阶段不修改世界。
- `MachineControllerBlockEntity`: 保存原来的方块状态快照、形成状态、方向、机器等级占位，避免拆除时丢失方块或复制物品。
- `MachinePartBlock`: 每一格的形成态部件；记录到 controller 的相对位置和形成方向。
- `FormationService` / `DisassemblyService`: 负责安全、幂等、可逆的世界变化；测试生存/创造/爆炸/重复触发/重新加载。
- `MachineView`: 初版用 18 个块的分段 JSON 模型共享边框，使其看起来是一台完整的大机器。未来静态部分用烘焙模型、可动画部分再用 BER，避免把整台静态机器按帧重画。
- `EnchantService`: 留接口，不在第一阶段接管附魔台菜单；后一阶段才定义 `RandomEnchantPolicy` 与 `DirectedEnchantPolicy`。

## 应测试的不变量（第二阶段概率系统）

- 相同物品、附魔池和书架配置下，所有设备等级都有机会出现高层次结果（抽样测试和概率模型检查）。
- 高设备等级对指定优质结果概率的影响方向正确，不出现意外归零。
- 禁止因随机加权跳过物品适配、附魔互斥、允许标签/禁用标签等规则。
- 计算经验花费由服务器完成；UI 不能决定最终附魔、扣费与随机种子。
- 附魔结果和费用都可由配置/数据驱动调节，而非散落在 Mixin 内的魔法常量。

## 第三轮：界面与预览分层

第二轮概率服务、候选池和种子机制保持不变。`PreviewPolicy` 是独立的纯 Java 信息策略：T1/2 显示结果稳定前缀 1 条、T3/4 最多 2 条、T5+ 全部，实际不足时不补假条目。

`MachineEnchantmentMenu` 仍缓存完整报价。`EnchantingPreviewPayload` 只同步已揭示条目和隐藏标记，并带容器 ID、报价版本、输入 ItemStack。原版 DataSlot 继续同步费用、T/B 和版本；客户端必须同时匹配容器、版本、输入才展示并允许点击。跨包的暂态只显示同步中，服务端仍拒绝所有过期点击。结果没有第二个预览 RNG，不发送完整隐藏结果或世界私盐。

`MachineGuiLayout` 是服务端槽位、客户端绘制/命中和测试共同依赖的纯几何，按用户视觉修正为 260×208，保留原版 9×3 背包与快捷栏。`MachineEnchantmentScreen` 继承 AbstractContainerScreen，直接引用原版附魔台底板、凹槽、棕色选项、绿色等级图标、符文和书本资源；没有新 PNG，也不改机器模型。选项正文仅显示符文和要求等级；所有真实结果与费用在可滚动、自动换行的 tooltip 中。第三轮时指定模式仅占位；第四轮已在同一区域启用真实列表与服务端规划，详见下节。

## 第四轮：铭纹石与指定附魔

- 铭纹石 `better_enchant:runic_stone`，Runic Stone / 铭纹石。每颗仅提供一步升级，没有时从 I 开始，已有时逐级升级到注册正常上限。普通合成和遗迹生成均未实现；创造材料栏或 `/give` 取得。
- 双槽复用：设备槽不变，第二槽在随机模式放青金石，在指定模式放铭纹石。切换模式不会兑换、删除或丢弃任何物品；放错材料会禁用操作，玩家自行取回。
- DirectedCandidates 读取完整附魔注册表、supported_items 和原版附魔存储组件；不以随机获取标签或 `isEnchantable()` 排除已附魔装备、盾牌、鞘翅等合法装备。默认不新增宝藏/诅咒，已有的仍保留。`better_enchant:excluded_from_directed` 和独立配置支持将来调整。
- DirectedEnchantPolicy 纯 Java 校验一步一步的分配、上限、互斥和费用；DirectedSession 管理每个菜单独立的有版本规划。列表直接显示规划完成后的附魔名与等级，没有时只显示名称；`+` 分配一步、`−` 只撤销规划，不降低物品原有等级。最多分配实际铭纹石数量，可一次计划多个兼容附魔。
- 取走/替换装备（即使序列化内容相同）、组件变化、关闭或重连清空未提交规划；铭纹石减少撤销最新超额步骤，增加不会自动恢复取消的步骤。机器等级变化保留合法目标但重算费用，成功数据包/配置 reload 清空规划并失效旧报价。书架仍只影响原随机策略。
- 客户端只提交模式/加/减/附魔动作、候选 ID 和版本，不提交费用、目标等级或完整结果。服务端检查当前玩家/容器/维度、整机、原输入对象与组件、当前注册表和标签、全部互斥、经验门槛与合计费用、实际铭纹石，准备独立输出副本后一次提交。
- 一律先达到30级并足够支付总费用；扣费后不必保持30级。指定模式包括创造玩家也实际消耗铭纹石和经验，创造仅提供取得材料的便利；随机创造模式原规则不改。
- 成功只更新 ItemStack 副本的相应附魔级别，保留其余附魔、名称、耐久和无关组件。随机种子不因指定操作而变化；已附魔物品仍不能再次随机附魔。
- **祛魔由未来另一台独立多方块机器负责**，当前机器永远不因此新增第三个标签页。本轮只写 [FUTURE_DISENCHANTING_MACHINE.md](FUTURE_DISENCHANTING_MACHINE.md)，没有新增提取成书或移除原有附魔的运行时代码；原随机模式的普通书附魔保持不变。

具体公式、交互、协议与验证见 [DIRECTED_ENCHANTING.md](DIRECTED_ENCHANTING.md)。第三轮原版风格保持不变，无新机器模型、能源、原创附魔或遗迹。

## 整机书架规则（0.4.2）

从机器3×3占地外扩2格，得到水平7×7减去机器自身3×3的区域；高度与机器上下两层一致，即相对上层中心控制器y=-1/0。共80个唯一候选，可紧贴、可放第二圈、角落和任意组合，不要求空气或传导通道。按原版 ENCHANTMENT_POWER_PROVIDER 标签识别原版与正常注册的第三方书架；只读已加载位置，不获取区块。有效数量和GUI显示上限36，36外不增加收益或重抽报价。

最小改造：纯Java BookshelfScan负责范围、去重和计数上限；MachineAccess只适配区块可用性/方块标签。RandomEnchantPolicy.Context饱和到0..36，负数拒绝。沿用现有种类、等级和多重公式，仅替换书架输入：默认0..15线性因子B/15，之后1+0.5×ln(B/15)，36封顶。bookshelf_scale允许1..36并改作转折点，新增bookshelf_tail_gain可配后段0.01..1；默认缺键自动兼容旧配置，临时数值仍待试玩。

原报价刷新机制按有效数量更新版本与服务端缓存并同步客户端；新上下文拒绝旧请求，恢复原上下文的源随机流不变。不改概率支持集、互斥、种子生成、渐进揭示、指定经验门槛与其GUI隐藏设计，也不改机器碰撞、模型或存储格式。公式与模拟见 ENCHANTING_BALANCE.md，实际测试与截图见 DEVLOG。

## 第四轮界面修正（0.4.1）

不改变菜单、规划协议、随机模型或服务器收费。原版纸质横条组成可滚动的指定附魔池，名称后直接显示服务端 target 等级；计划增加的条目用暗绿文字标识。原有等级没有被真实降低，撤销只退回未支付的计划。小加减按钮沿用原版 widget；无可撤销步骤时减号灰置，达到正常上限时加号隐藏，预算/互斥限制则加号灰置。

随机模式使用原版纸质选项、禁用与悬停 sprite，资源不足也仍有清晰悬停。红色等级数字与红色细线表示经验不足，蓝色细线表示青金石不足；两者同时不足则双色线。真实结果仍只在 tooltip 展示，银河字母与绿色要求等级保留。

指定界面按此次要求移除“需30级”提示；**现有服务端30级使用门槛保留**，没有把这次显示修正解释为经济规则改动。下方仅显示铭纹石已用/实际数量、实际总费用与“附魔”。tooltip 使用原版样式，限定换行宽度与页高并放在列表下方，长名称按 Shift+滚轮完整读取；没有臆造注册表未提供的附魔效果说明。非默认字体和资源包仍需整合验证。
