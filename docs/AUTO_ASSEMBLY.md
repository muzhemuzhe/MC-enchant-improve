# 三台机器自动组装 · 0.12.0

三台机器沿用原有3×3×2材料、状态判定、事务、原始快照、拆解和已成形模型/碰撞。放下最后一块合法材料后，服务器在下一世界tick自动形成。中心可以先放，最后补下层或边角也可以；不需要潜行、空手或右键确认。

| 机器 | 下层 | 上层 |
| --- | --- | --- |
| 附魔机 | 磨制深板岩×9 | 紫水晶块四角、黑曜石四边、原版附魔台中心 |
| 研究台 | 石英×8、錾制石英中心 | 普通书架四角、朝中心的空讲台四边、原研究台中心 |
| 祛魔台 | 紫水晶块×8、金块中心 | 朝上的成熟紫水晶簇四角、红石四边、原祛魔核心中心 |

研究台同时校验讲台HAS_BOOK与实际书本数据，放着书的讲台仍拒绝组装；祛魔台仍要求成熟/朝UP/受支撑的晶簇，含水快照仍保留。形状、材料与[原有状态恢复规则](WORKSTATION_STRUCTURES.md)不改。

## 事件与事务

- AutoAssemblyStateMixin在官方Level.setBlock四参数重载成功返回后通知，只接收ServerLevel。原版物品放置、普通状态修正和经过Level的命令/结构修改都能触发。
- AutoAssembly先按固定材料集合过滤；以变更格位反推现有18格相对坐标对应的候选中心。只有本地已加载且确实有对应原控制器时入队。每世界用候选类型+中心去重，下一END_LEVEL_TICK验证，无全世界逐tick扫描。
- 形成仍调用原FormationService或WorkstationStructure.form；先确认18格已加载。失败不写材料；成功切换原模型，播放一次低音量附魔台音效和12粒短暂附魔粒子。成形技术部件不属于候选材料，不递归形成自己。
- 区块首次CHUNK_LOAD，以及缓存区块从INACCESSIBLE恢复FULL，均延迟局部扫描。只在含控制器的section使用palette预筛，扫描新可访问区块与相邻一格边界，找回未成形控制器；没有getChunk加载请求、区块票或远程扫描。等待可访问时不读取未加载区块，离开可访问状态或卸载时取消相关扫描。
- 原附魔机自动形成采用NORTH的固定表现朝向，其模板本身四向对称。研究台讲台仍按相对中心方向，中央原FACING保存；祛魔台成熟簇仍朝UP。
- 旧Shift右击不再执行形成。独立研究/祛魔控制器只提示检查结构；独立原版附魔台仍拦截玩家原版菜单，已经成形的原附魔机Shift右击仍为原有状态查询。
- 破坏任一部件继续沿用原服务恢复其他材料。缺口补齐后自动再次形成并取得新UUID，旧菜单不会因此重新获得交易权限。未成形的完整旧存档框架在加载后也能被发现；已经成形的存档继续同UUID，无免费重建或转换。

原版独立附魔台是[附魔师](ENCHANTER.md)工作站，形成后的技术部件不是POI。原Level.setBlock的POI更新仍正常执行，形成时移除原工作站记录，拆解恢复时再加入；不手工强改村民职业或记忆。讲台的原版POI也按相同原生更新处理。

现有随机/指定附魔、12点充能、研究世界映射与发现、结果领取事务、祛魔诅咒/费用均不改。新自动事件不改变三台已成形外观和碰撞。

## 0.13.0进度归属

自动形成队列现在短暂携带实际方块交互发起者，成功形成才授予对应原生进度。最近的材料变更决定归属；非玩家修改不会沿用旧玩家，载入扫描不覆盖实际操作。没有附近群发，也没有重新引入手动组装。见[六项进度与边界](ADVANCEMENTS.md)。
