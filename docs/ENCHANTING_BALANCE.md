# 第二轮随机附魔：临时概率模型与实验

日期：2026-10-16。目标版本：Minecraft Java 26.1.2 / Fabric。这里记录可调整的原型，不是长期平衡承诺。没有指定附魔、原创附魔、新宝藏来源、升级配方或能源系统。

## 实际输入和分层

- `MachineControllerBlockEntity` 的 controller 保存机器 tier；旧存档缺字段时为 1。新形成机器采用服务器 default tier。管理员命令可修改并正常存档；拆解再形成采用默认等级，不把管理员测试等级转移到原版材料中。
- `MachineAccess` 验证完整且已加载的 18 格、UUID 和位置；书架扫描与等级独立。
- `EnchantmentCandidates` 读取当前世界附魔注册表、标签和物品组件，输出纯数据候选池及互斥关系。
- `RandomEnchantPolicy` 是不引用 Minecraft 的 Java 服务；只计算种类、等级和多重附魔。菜单不定义概率公式。
- `MachineEnchantmentMenu` 管理每名玩家各自的两个暂存槽、报价、服务端验证和一次提交。第二轮客户端复用原版画面；第三轮换为自定义像素界面，报价和扣费模型不变。

## 合法候选支持集

原始池来自 `minecraft:in_enchanting_table`，额外排除 `minecraft:treasure`、`minecraft:curse` 和 `better_enchant:excluded_from_random`。本轮配置不能打开额外宝藏或诅咒。物品需要原版 ENCHANTABLE 组件、空 ENCHANTMENTS、数量为 1。非书物品使用附魔的 `isPrimaryItem`（包含 supported_items 和 primary_items 判断）；普通书按原版可存储池内附魔，结果转为附魔书。已经附魔的装备/附魔书不再次附魔。

不使用附魔名称白名单，也不通过 `getMinCost/getMaxCost` 筛选附魔等级。每个合法候选保留注册定义的所有 `minLevel..maxLevel`；这些 cost 字段在此不再充当等级获取门槛。注册数据的物品适配、最大等级和 exclusive_set 仍有效。其他模组需要按数据约定将附魔加入 table tag、给物品适当组件/标签，才参与抽取；不会无条件开放它们刻意排除的附魔。

`type_multiplier.<registry-id>=0` 是显式配置禁用，不属于“配置允许”支持集。正倍率限制为 0.01..100，不能用负数、NaN 或无穷权重。运行时非法参数拒绝加载；失败的 reload 保持旧配置。

## 两个独立的分布轴

记机器等级 T，实际有效书架数 B，选项索引 o=0/1/2，书架缩放 S（默认 15）。`s=min(B,S)/S`，`t=T-1`。

**种类：**注册定义原始权重为 w(e)>0，配置倍率 m(e)>0。

```text
alpha = 1 / (1 + rarity.tier*t + rarity.shelves*s + rarity.option*o)
W(e) = m(e) * w(e)^alpha
P(first=e) = W(e) / sum(W)
```

低等级接近原版权重关系；提高等级/书架让 alpha 下降，较稀有（较小 w）的相对机会提高，趋向较平坦分布。没有给稀有附魔新增解锁列表。这里的“稀有”按原始注册权重度量，游戏数据没有要求所有模组使用同一常见/稀有枚举。

**某个已选附魔的等级：**对它的每个合法等级 L，`x=(L-min)/(max-min)`；只有一个合法等级时 x=0。

```text
q = clamp(level.base + level.tier*t + level.shelves*s + level.option*o, -12, 12)
V(L) = exp(q*x)
P(L | e) = V(L) / sum(V)
```

`rarity.*` 与 `level.*` 可以独立调整。归一化等级让不同最大等级的附魔使用同一条曲线，但也意味着 II 是某附魔最高级时，不能与锋利 II 当作等价品质。这是需要试玩评估的简化。

**严格非零依据：**有限合法池中，w、m 严格正且有限；alpha 有限，q 有界，exp(q*x) 严格正且有限。因此对任意合法附魔及其任一合法等级，`P(first=e)*P(L|e)>0`，包括 T=1、B=0、选项一的最高等级。后续互斥过滤不能消除它作为第一个结果的概率。所有机器等级共享同一支持集，除显式配置禁用外无零概率门槛。

**改善概率的边界：**alpha 下降提高较小 w 相对较大 w 的几率；q 增大对固定附魔的归一化等级分布做向上的指数倾斜，最高等级概率单调增加。相同合法池、正默认提升系数下，这两项有解析保证。不能据此声称每一个具体附魔的“整件装备中出现概率”都严格递增：互斥竞争、多重次数和它的原始稀有度会共同作用。配置把某一轴增益设为 0 时，该轴自然不改善；到达曲线夹取/书架上限后收益也会平台化。

## 多重附魔

```text
p = clamp(extra.base + extra.tier*t + extra.shelves*s + extra.option*o, 0, 0.8)
先选一个合法种类和等级。
已经选了 k 个后，以 p/k 的概率继续；总数不超过 max_enchantments。
每次从剩余池中删除已选种类及与任何已选附魔互斥的种类。
```

禁止重复种类；互斥双向检查适配 Minecraft 的 `Enchantment.areCompatible`，不只检查最后一个附魔。最大数量默认 4（配置 1..6），并非保证抽到四个。附魔书也遵循同一套规则，不再额外随机删一项；这是本轮相对于原版书本的临时差别。

## 书架

沿用原版 `EnchantingTableBlock.BOOKSHELF_OFFSETS`（相对 controller 水平两格环、y=0/1，共 32 个候选位置），使用 ENCHANTMENT_POWER_PROVIDER 与 ENCHANTMENT_POWER_TRANSMITTER 标签。仅在 provider 和中间通道所在区块已加载时读取。

由于机器自身占 3×3 区域，完全照搬原版通道判断会让同高度书架全部被技术部件挡住。因此仅属于本机 UUID/controller 的中间部件视为可传导，其他障碍仍阻挡；没有全局修改普通附魔台/方块标签。屏幕 B 显示实际扫描数，概率默认在 15 架达到书架收益上限，S 可改到 32。零书架仍有全部合法等级的支持，没有某个书架数才开放新附魔的门槛。

## 临时参数及费用

启动生成 `config/better_enchant.properties`；完整默认文件在 `src/main/resources/better_enchant-defaults.properties`。单人测试/开发实例的文件位于相应游戏目录 config/，不是仓库根目录配置。命令 `/better_enchant reload` 原子替换配置快照。

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| default_machine_tier / max_machine_tier | 1 / 5 | 默认形成等级与管理员调整上限；支持最大 10，非升级设计承诺 |
| bookshelf_scale | 15 | 书架收益饱和点 |
| rarity.tier / shelves / option | 0.35 / 0.8 / 0.2 | 种类分布变平的速度 |
| level.base | -4.0 | 基础等级曲线，偏向低级 |
| level.tier / shelves / option | 0.8 / 2.0 / 0.6 | 高等级附魔倾斜增益 |
| extra.base / tier / shelves / option | 0.15 / 0.04 / 0.15 / 0.1 | 多重继续概率 |
| max_enchantments | 4 | 多重数量上限 |
| required_level.1 / .2 / .3 | 5 / 15 / 30 | 屏幕显示的经验等级要求，与实际扣除分开 |
| type_multiplier.<id> | 未配置时 1 | 每个类型的独立倍率；0 禁用 |

Java properties 的 key 中冒号需要转义，例如 `type_multiplier.example\:enchantment=0.5`。不要把第三方数据条目名称写成源码白名单。

三选项沿用原版操作：要求屏幕上的经验等级，**实际扣除 1/2/3 个经验等级和相同数量青金石**；不是扣 5/15/30 等级，也不是扣固定 XP 点。使用原版 `onEnchantmentPerformed`，保留原版 XP 进度处理。创造模式免费但仍更新玩家种子。三个选项只提供不同倾向，不保证第三项每次胜过第一项。

## 种子、报价和多人

世界 SavedData 保存不发送客户端的私有随机盐；与玩家 UUID、原版 enchantmentSeed 和选项组合。等级、书架、机器坐标/UUID不用于产生新的源随机数，因此同一玩家、同一物品、同一上下文关闭重开、取出放回、换机器和正常保存重进均不会获得新的一组结果。物品候选池按 registry ID 排序，避免注册/HashMap 迭代顺序造成重抽。成功附魔才更新原版玩家种子；新玩家为 0 的原版存档哨兵在首次报价前初始化，避免第一次保存重进意外变化。

修改物品、书架、tier 或配置确实会改变分布/候选，使用相同底层随机流得到新的确定性报价。这保留了一定的原版“换物品/挪书架比较选项”能力，不声称完全消除所有选项侦察。禁止的是无代价关闭/重开、反复拿放相同物品、拆装相同机器引起独立重抽。

客户端只同步原版费用/提示、T/B、外观种子及报价版本，完整结果在服务端缓存。报价版本通过标准 container button VarInt 传送（29 位版本+2 位选项），DataSlot 拆两段同步；输入或上下文改变即换版本。旧/重复请求在扣费前拒绝，成功后输出已附魔物品不再符合输入规则。服务器提交前重查结构身份/距离/当前池/费用/全部互斥。每名玩家独立槽与种子，两人使用同一机器不共享库存；服务端串行提交。正常关闭/拆解/距离失效由原版容器归还物品。

## 已知不平衡和未决问题

- T5+B15 最高级比例较高，平均近两个附魔；是否过于慷慨需要试玩。等级提升不增加费用，本轮只有管理员测试切级，没有生存升级成本。
- 归一化等级并不等价于实际战斗价值；低等级也可能抽到强组合。不同物品池的大小、稀有度约定和互斥关系会使收益不同。
- 原版物品 enchantability 作为能否附魔的组件条件保留，但其数值没有额外加成，金装备当前没有原版的概率优势。这是明确的原型简化，后续可加独立可测轴。
- 书本采用相同多重流程，不做原版额外删项；书本与装备的相对收益未定。
- 只模拟固定钻石剑和合成兼容性池；并未完成所有装备、所有第三方大模组或完整经济系统的平衡调查。
- 保护/领地模组、其他替换同一菜单/屏幕/交互的模组可能冲突；没有声明完全兼容。用注册与标签夹具验证兼容边界，不代表整合包实测。
- 多人仅同服务端双玩家菜单自动测试；尚未两台独立客户端的网络抖动/断线压力测试。跨区块正常存档已回归，真实单侧卸载恢复和崩溃一致性仍沿用第一轮限制。
- 指定附魔、升级方式、宝藏获取、机器等级个数和长期费用都未决定，本轮不实现。

## 第三轮信息揭示（临时规则）

机器 T1/2 揭示每个已缓存结果的第 1 条，T3/4 揭示前 2 条，T5+ 揭示全部；不足时显示实际条数，存在其余结果才显示 ???。揭示不消耗随机数，不改变任何种类、等级、多重次数或费用参数。固定相同种子、物品和上下文，取出放回、关闭重开、正常断线重进都保持内容与顺序。改变 T/B 会按原算法更新上下文，所以可以改变结果；旧版本请求拒绝。

这是信息量的临时台阶，与所有等级共享完整合法附魔支持集的规则不同：没有增加任何附魔获取解锁条件。长期揭示方案、信息价值与最高级全部公开的强度仍需试玩，本轮未替用户定案。第三轮继续跑相同真实钻石剑 6×100,000 抽样作为回归，并与第二轮逐文件比较。

## 第四轮指定费用

随机策略和上面固定种子输出保持不变。指定模式采用独立、无随机数的逐步费用模型：30级门槛，每步一颗铭纹石和5–8经验等级；批量先逐步计费再合计，高机器等级可折扣到5级下限。参数、例子、已知未平衡点见 [DIRECTED_ENCHANTING.md](DIRECTED_ENCHANTING.md)。不把这套数值视为最终经济，不涉及遗迹掉落平衡。
