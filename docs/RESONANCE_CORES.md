# 共鸣核心与 Lv.2（充能规则沿用0.5.0，现更新至0.8.0）

0.8.0谐调核心已有实际用途：[失落魔法研究台](LOST_RESEARCH.md)每次研究消耗现有 `differentenchant:attuned_resonance_core` 一颗；没有注册第二种不兼容材料。无论产出失落附魔书还是固定失落卷轴均消耗一颗，研究不额外扣经验。12点充能、普通/谐调核心转化、重复生产和Lv.1→Lv.2规则不变。

0.6.0新增的工坊顶层箱子有1/50独立概率获得一个未充能普通核心；不会直接提供谐调核心，也不改变本节12点生产与升级规则。遗迹中的青金石块/书/铁锭亦可支持原配方，见 [RUINS](RUINS.md)。

共鸣核心是可反复生产的材料链。没有核心仍可正常附魔，不积攒可事后领取的能量。上限固定 **12点**，本轮没有容量配置，因此不会因服务器改配置而丢弃已有物品；读到负值或超大值时计算和显示饱和到0..12，不让非法数值破坏整份物品存档。

## 合成与物品

`differentenchant:resonance_core`（共鸣核心 / Resonance Core）最大堆叠1，初始能量0。原生3×3有序配方：

```text
C A C
A L A
C A C
```

C是铁锭，A是普通书或任意附魔书，L是青金石块。四个书位可自由混用，不限制附魔书的附魔种类、等级或条数。原生Ingredient集合只匹配物品ID；正常消耗四铁锭、四书、一青金石块，产出一个无充能核心，不转移书的附魔。

`differentenchant:attuned_resonance_core`（谐调的共鸣核心 / Attuned Resonance Core）没有直接配方，无额外状态时堆叠64。创造材料栏提供两者，亦可用 `/give @s differentenchant:resonance_core` 测试。贴图为 `tools/generate-resonance-cores.ps1` 生成的原创16×16像素：普通核心铁框深蓝晶体，谐调核心金色框与亮青晶体；不改整机模型。

## 收集与升级

- 服务端随机附魔成功且实际支付1/2/3经验等级后，给当前安装的一颗普通核心增加1/2/3点。
- 指定附魔成功后增加该批次实际支付的经验等级合计，不额外收费，每步5–8级和30级使用门槛保持。**创造模式两种模式均不产生能量**，即使指定模式仍按既有规则支付费用。
- 满12时自动转为一枚谐调核心，保留在槽里。能量超过剩余容量部分丢弃，不给下一颗核心，不积攒到账户。
- 当前机器真实等级等于1时同时保存为2；2及以上不提升。完成时播放附魔粒子与升级音效；菜单下一次同步刷新等级、随机报价及指定费用。原等级配置仍限制算法使用的有效等级，存储的已获升级不会因降低配置而回退。
- 打开、预览、加减、取消、失败、重放和没有核心时的历史附魔不充能。留下成品继续附魔也不会多产成品；必须取走并安装新普通核心。

## 库存、同步与拆解

控制器独占一个SimpleContainer持久槽，菜单尾部追加核心槽38。原装备/材料槽0/1及玩家槽2..37编号和坐标不变；核心位于背包左侧预留留白，和独立小进度条0/12..12/12组成一列。两种模式共用核心槽，无新页签。物品悬停在机器或原版容器中均显示真实组件能量/成品说明，中英文均提供。GUI只读原生菜单同步后的ItemStack，不发送客户端充能或升级指令。

`differentenchant:resonance_energy` 是注册的Integer数据组件，具有持久Codec和网络StreamCodec。充能替换物品副本并标记控制器保存；转化用transmuteCopy并只移除本组件，保留无关组件。控制器 `resonance_core` 字段用ItemStack.OPTIONAL_CODEC存储，旧存档无字段按空槽加载。只有控制器保存核心，17个从属部件不复制它。

核心是共享机器库存，装备/材料和指定计划仍归各菜单。服务器线程串行处理多个玩家取放和附魔；每次成功只更新当时安装的物品。关闭/断线仅返还原临时槽与鼠标持物，不返还安装的核心。Shift转移显式区分核心38与玩家2..37，安装槽最大1，支持成品从堆叠中取一枚安装。菜单失效后不允许通过旧核心槽取放。

拆解先从已加载控制器取走并清空核心，再掉落一次，然后还原18格；被破坏的控制器自身也通过原实体引用清空。重复回调、恢复过程中嵌套回调和旧菜单不会重新返还。控制器未加载时不读取它；残留控制器加载后由原完整性检查发现已缺部件，自行清空掉落并恢复。拆解生产物品不依赖是否创造模式或破坏工具，不修改原材料掉落规则。

这是正常服务器线程与世界保存流程中的一次提交，不提供对操作系统崩溃中途、第三方强制删除BlockEntity而绕过移除钩子的数据库式事务保证。随机算法、私盐与真实结果缓存、互斥/标签、36架收益、碰撞和原版台使用规则均保持。
